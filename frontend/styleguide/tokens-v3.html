「太实心」有两层原因，我两条都改

这两件事通常是叠加出现的，所以我一起处理：

  • 实心块太多。你不止一个实心按钮——工具栏里「一键通过 / 导出」都实心，三张统计卡全是满色底，状态标签也是填充。整屏有 8–10 个实心色块互抢注意力，就会显得"糊"。修法：一屏只留一个实心块，其余降到柔和或描边。
  • 颜色本身太饱和。我上一版给的 #0f766e、#4f46e5、#1d4ed8 都是中等饱和的品牌色，大面积填充时很重。修法：换成低饱和、高明度的色阶——下面 5 套都是往灰里调过的。

顶部两个开关：左边换配色，中间换实心密度。下面我会解释「一实心」为什么是我最推荐的档。

01 修法一 · 降低实心密度

问题通常在这里，而不是色相

一个界面里实心色的数量是有预算的。每一块满色填充都在说"看我"，超过一两个，用户就失去焦点、整屏变沉。下面是同一段工具栏的四种密度。

同一段工具栏 · 密度对比

档 A 一实心 · 只有「一键通过」满色，其余柔和 —— 推荐

思路：实心 = 不可逆 / 本周最重要的一次动作。「一键通过」会批量改动数据，值得满色；「导出」只是读取，用柔和。

档 B 全柔和 · 一个实心都没有
待补材料 已打回

最轻盈。代价：主操作和状态标签长得很像（都是"浅底 + 描边 + 彩字"），用户不容易一眼找到"该点哪个"。

档 C 全描边 · 只剩白底和线
待提交待补材料

最克制，接近"财务软件"观感。但主按钮弱化得比较厉害，批量操作这种"有后果"的动作用描边略欠分量。

我推荐档 A（一实心）。它不是"少用颜色"，而是把颜色当预算花：整屏只留一个满色，那个位置就自动变成"最该点的地方"。这也正好接上你已确认的意见 05（一屏一个主操作）——两件事是同一个道理，可以一起做。

这 5 套共同守的三条

  • 避开状态色相。红/琥珀/灰已占掉三个区间，主色必须离它们够远。这是我把赭石标注为"要改待补色"、把旧版松绿直接淘汰的原因。
  • 柔和档够明显。柔和底与描边之间至少有 1.2 的对比，浅底也看得清边界（5 套都验过）。

06 配置片段

选定后我照着写

配色 token（以烟蓝为例，其余同理）

// 每条色阶四个值：solid 只给唯一的实心块，其余用 subtle + border
accent: {
  DEFAULT: "#3d5a80",   // 唯一的实心底（白字对比 7.06）
  text:    "#3d5a80",   // 柔和底上的字（对比 6.34）
  subtle:  "#eff3f8",   // 柔和底
  border:  "#c6d3e4",   // 柔和描边
  hover:   "#33506f"
},
// 状态色（中性/琥珀/玫红/灰）保持不变，已验过对比度
// 唯一规则变化：action 态跟随 accent，其余四态与配色无关

按钮轻重三档

/* 默认：柔和档。实心只通过 .is-anchor 授予，一屏一个 */
.btn-prime { @apply bg-accent-subtle text-accent-text border border-accent-border; }

/* 一实心档（推荐）：只有带 is-anchor 的主操作是满色 */
.btn-prime.is-anchor { @apply bg-accent text-white border-transparent; }

/* 全实心档：想让某类页面更"重"时启用 */
/* 全描边档：想让某类页面更"轻"时启用 */

/* 尺寸同时收窄（已确认） */
.btn    { @apply h-control-sm; }   /* 32px，页面级 */
.btn-xs { @apply h-control-xs; }   /* 28px，表格行内 */
.btn-lg { @apply h-control-lg; }   /* 36px，仅登录页 */
还需要你定两件。① 配色选哪套（我推荐烟蓝，次选石墨）；② 实心密度选哪档（我推荐一实心）。按钮 32px、field-inline 保留、意见 01/02/03/05 都已按你的确认记下，等这两项定完我就开始改代码。
