把散落的样式值收成一套 token

页面显得死板，不是因为配色选错，而是因为颜色、圆角、阴影、按钮高度、容器宽度都在每一处单独决定：圆角现在有 5 档（6/12/16/24/…）、页面容器 5 种宽度、按钮 4 种高度，而且同一个"近黑"和同一个"已提交"状态各有两种表现。下面是我准备落进 tailwind.config.js 的 token，以及它们应用后的实际长相。

本页是独立 HTML，直接双击浏览器打开即可，不会进入 vite 打包，也不影响现有页面。

怎么读这份 gallery

先看这 3 条
  • 看颜色和圆角即可判断大半：下面每个色块旁都标了 hex，和我准备写进配置里的值完全一致。你改哪个，我改哪个。
  • 阴影那一节是重点：现在的层级是反的（子元素浮起、父容器扁平），这是"像线框图/Excel"的主因，第 5 节有并排对照。
  • 第 8 节是现状审计：把两个近黑、状态色冲突、圆角混用这些具体问题并排摆出来，方便你判断我的诊断对不对。
三条硬规则（后面每节都遵守）
  • teal 只表示"需要你动手"。一旦进入"等审核/已归档"，就降为中性灰。现在 teal 同时表示"待提交"和"已提交"，用户建不起颜色映射。
  • 一个近黑：正文只用 #0f172a，删掉偏绿的 ink #10231f。
  • 面板浮起、面板内贴片扁平：阴影方向现在正好相反。

02 状态语义

5 组，每组 bg / border / text 三件套

这是修掉"同一状态两种颜色"的关键。每组都是一个整体，页面里不再单独挑色。橙色（现在用于"替票"）并入 amber——它和"待补材料"的 amber 只差一点色相，却是两个含义，合并后少一种颜色。

neutral · 无需操作已提交等审核、信息展示bg #f1f5f9 / bd #e2e8f0 / tx #475569
action · 该你动手待提交、可提交、主操作bg #f0fdfa / bd #99f6e4 / tx #0f766e
warn · 缺料 / 待补待补材料、替票说明待填bg #fffbeb / bd #fde68a / tx #b45309
danger · 被打回已打回、不可用抬头bg #fff1f2 / bd #fecdd3 / tx #be123c
done · 已归档已完成，降级显示bg #f8fafc / bd #e2e8f0 / tx #64748b

04 圆角

从 5 档收到 3 档 + pill

现在有 6 / 12 / 16 / 24px 在混用（rounded-md 34 次、lg 25 次、xl 11 次、2xl 3 次、3xl 3 次）。按"用途"而非"感觉"来分：控件、小贴片、容器。

radius-smchip、缩略图
8px
radius-control按钮、输入框
16px
radius-panel面板、弹窗、统计卡
999px
radius-pill状态标签
容器从 24px 收到 16px、控件从 6px 提到 8px，是"看起来柔和"的主要来源之一——不是把东西都变圆，而是让同一类东西圆得一样。

05 阴影与层级

3 档，方向掰正

这是"死板"的根因。现在面板用的是 shadow-line——它其实只是 0 1px 0 rgba(15,23,42,.06)，一条发丝线，不是阴影；而面板内部的缩略图却用了 shadow-sm。结果是子元素浮起来、父容器是个扁平矩形，整页读起来像线框图。

06 间距与布局

4px 基数，一个容器宽度

页面容器现在有 5 种（max-w-3xl / 5xl / 6xl / 7xl / 88rem），垂直节奏 4 种。收成一个容器宽度 + 一个节奏，侧栏切换时页面就不会"呼吸忽大忽小"。

布局常量
  • 页面容器：单一 max-w-[88rem]，左右留白 16 / 24 / 32px（随断点）。
  • 区块节奏：统一 space-y-6（现在是 5/6/7/8 混用）。
  • 控件高度：32px（sm，行内）/ 40px（md，页面级）。现在是 7/8/9/10 四种。

07 组件应用

09 配置片段

你点头后我照着写进代码

tailwind.config.js（theme.extend）

// 用语义名，不再让页面直接写 teal-700 / slate-400
theme: {
  extend: {
    colors: {
      accent: { DEFAULT: "#0f766e", hover: "#115e59", subtle: "#f0fdfa", border: "#99f6e4" },
      surface: { DEFAULT: "#ffffff", canvas: "#f8faf9", subtle: "#f8fafc", muted: "#f1f5f9" },
      hairline: "#e2e8f0",
      strong:   "#cbd5e1",
      // 状态三件套：bg / bd / tx
      state: {
        neutral: { bg: "#f1f5f9", bd: "#e2e8f0", tx: "#475569" },
        action:  { bg: "#f0fdfa", bd: "#99f6e4", tx: "#0f766e" },
        warn:    { bg: "#fffbeb", bd: "#fde68a", tx: "#b45309" },
        danger:  { bg: "#fff1f2", bd: "#fecdd3", tx: "#be123c" },
        done:    { bg: "#f8fafc", bd: "#e2e8f0", tx: "#64748b" }
      }
    },
    borderRadius: { sm: "6px", control: "8px", panel: "16px" },
    boxShadow: {
      flat:    "0 0 0 1px rgba(15,23,42,.04)",
      raised:  "0 1px 2px rgba(15,23,42,.04), 0 4px 12px -2px rgba(15,23,42,.06)",
      overlay: "0 8px 16px -4px rgba(15,23,42,.10), 0 24px 48px -12px rgba(15,23,42,.18)"
    },
    height: { "control-sm": "32px", "control-md": "40px" }
  }
}

同时删除的 15 个死类

这些在 style.css 里零引用，是 V1 工作台的残留，约 100 行（占该文件三分之一）。它们让设计系统看起来比实际成熟，也会误导下一个改样式的人。

action-banner* guide-hint field-textarea intake-grid record-connector record-link-button record-link-caption work-bar-panel match-mini-stat match-progress-* match-invoice-row match-empty-copy
需要你定两件事。 ①字体：自托管 Inter，还是明确改用系统字体栈（本页即后者）？②首页快捷录入的下划线输入要不要保留为 field-inline 变体，还是统一成标准输入框？其余 token 我建议直接按上图执行。
