# JetBao Product

## production

### 用户是谁

- 普通员工：日常记录和提交自己的报销。
- 管理员：既是员工，也拥有维护账号、核对台账和导出 Excel 的权限。

### 核心价值

把零散票据和临时报销事项整理成可核对、可导出的月度台账。

### 产品原则

- 账号代表真实员工，权限决定可见页面；管理员不通过切换账号处理个人报销。
- 公司主体固定为三个：`上海山途远智信息科技有限公司`、`山途远智（上海）企业服务有限公司`、`上海山途远智企业咨询有限公司`；员工账号只能从下拉中绑定其中一个。
- `随手记` 是待补材料的报销记录，不是独立记账功能。
- 花费项目是报销主线；发票是凭证，交易记录附件属于花费项目本身。
- 一条花费可以匹配多张发票；一张发票只能归属一条花费。
- 三个公司主体的发票抬头都可以用于报销整理；OCR 只识别到部分抬头时必须提示用户人工确认。
- 员工不能用小额发票先部分提交大额花费；票面金额达到花费金额后才保存匹配并进入提交判断。
- 工作台同一轮新建花费并上传发票时，上传先完成 OCR 并暂存，后续由按钮决定加入池子还是直接记录该笔。
- 待定池里的错误花费、错误发票和错误交易记录附件都必须能删除。
- 员工可以自己修改登录密码。
- 员工侧先解决记录完整性，管理员侧解决月度核账和导出。
- 导出只交付已提交的完整记录，待补材料只用于提醒和追缺。
- 已提交记录是正式报销数据，员工侧不能继续追加发票或交易附件；改错后续通过撤回/作废动作单独设计。

### 不做什么

- 不做管理员代登录员工账号。
- 不做完整审批流。
- 不把没有佐证材料的随手记混进正式导出台账。
- 不保留无发票匹配的直接提交入口。

### 用户体验路径

- 普通员工：我的报销 -> 记一笔 -> 花费池（可补交易记录图片/附件） -> 匹配发票 -> 已提交。
- 普通员工已有发票：报销整理工作台 -> 上传发票 -> 发票池 -> 匹配花费项目 -> 已提交。
- 普通员工材料齐全：报销整理工作台 -> 上传发票完成 OCR -> 记录该笔 -> 已提交。
- 普通员工在工作台同一轮记花费并上传发票：点“加入发票池”则把已解析发票发布到发票池；中间“记录该笔”按金额判断，票面金额小于花费金额时等待继续上传，相等时直接绑定，高于时直接绑定并标记为替票。
- 管理员个人报销：我的报销 -> 记一笔，或进入报销整理工作台匹配花费和发票。
- 管理员工作区切换：同一账号内从“个人”切到“管理”，不切换员工身份。
- 管理员核账：管理后台 -> 按状态/月份/员工筛选 -> 查看待补材料或已提交记录。
- 管理员导出：导出 -> 预览已提交汇总 -> 看到待补材料提醒 -> 导出 Excel 或完整明细包。

## ux

### 设计原则如何回应以上要求

- `记一笔` 放在我的报销页，以浮层小卡片完成快速记录。
- 随手记只记录项目名称、金额、月份和类别，不收备注。
- 报销整理工作台上方是工作栏：左侧花费、右侧发票，中间按钮表达当前动作；下方左侧是花费池，右侧是发票池。
- 工作台顶部录入区以按钮表达意图：上传发票时先 OCR 并暂存，“记录该笔”放在花费和发票之间，只有金额可形成完整记录时亮起。
- 工作栏不悬浮遮挡下方池子；花费池和发票池是主要管理区域。
- 我的报销页和报销整理工作栏都提供交易附件上传入口；这些图片只证明真实付款或订单，不参与发票匹配。
- 发票池条目来自 OCR 识别出的真实发票，不展示已挂到花费项目上的交易记录附件。
- 花费卡片、交易记录附件和发票卡片都提供删除入口，防止误录入卡在待定池里。
- 工作栏支持给同一条花费选择多张发票，不提供单张发票拆分到多条花费的入口。
- 普通用户通过顶部栏进入修改密码，不新增独立设置页。
- 匹配完成后才形成可导出的已提交报销项。
- 管理员用侧边栏切换“个人/管理”工作区；个人区保留自己的报销路径，管理区只放台账、员工和导出。
- 导出页默认面向完整台账，同时提示还剩多少记录未补完整。
- 明细包包含多 Sheet Excel 和按月份、公司、员工、报销项归档的附件文件夹。
- Excel 首页先汇总公司主体和人员维度，财务确认主体归属后再进入明细 sheet。
