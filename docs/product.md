# JetBao Product

## production

### 用户是谁

- 普通员工：日常记录和提交自己的报销。
- 管理员：既是员工，也拥有维护账号、核对台账和导出 Excel 的权限。

### 核心价值

把零散票据和临时报销事项整理成可核对、可导出的月度台账。

### 产品原则

- 账号代表真实员工，权限决定可见页面；管理员不通过切换账号处理个人报销。
- 公司主体固定为三个：`上海山途远智信息科技有限公司`、`山途远智（上海）企业服务有限公司`、`上海山途远智企业咨询有限公司`；员工账号只能从下拉中绑定其中一个。
- `随手记` 是待补材料的报销记录，不是独立记账功能。
- 花费项目是报销主线；发票是凭证，交易记录附件属于花费项目本身。
- 一条花费可以匹配多张发票；一张发票只能归属一条花费。
- 三个公司主体的发票抬头都可以用于报销整理；OCR 只识别到部分抬头时必须提示用户人工确认。
- 发票票面金额等于报销金额时是实票，高于报销金额时标记替票，低于时继续待补；员工界面不展示金额差额，不把差额作为用户需要处理的流程。
- 工作台同一轮新建花费并上传发票时，上传先完成 OCR 并暂存，后续由按钮决定加入池子还是直接记录该笔。
- 待定池里的错误花费、错误发票和错误交易记录附件都必须能删除。
- 员工可以自己修改登录密码。
- 员工侧先解决记录完整性，管理员侧解决月度核账和导出。
- 导出只交付已提交的完整记录，待补材料只用于提醒和追缺。
- 已提交记录是正式报销数据，员工侧不能继续追加发票或交易附件；改错后续通过撤回/作废动作单独设计。

### 不做什么

- 不做管理员代登录员工账号。
- 不做完整审批流。
- 不把没有佐证材料的随手记混进正式导出台账。
- 不保留无发票匹配的直接提交入口。

### 用户体验路径

- 普通员工：我的报销 -> 新建报销 -> 填写花费 -> 上传或选择发票 -> 系统匹配 -> 提交。
- 普通员工待补材料：待补材料 -> 随手记一笔或单独传发票 -> 后续补齐另一半 -> 形成完整报销 -> 提交。
- 普通员工已有发票：从某一笔报销记录里选择“添加发票”，再上传新发票或选择已有发票；发票池不作为普通员工的一等入口。
- 普通员工只传发票：从“待补材料”上传发票并完成 OCR，后续在某一笔报销里通过“选择已有发票”使用，或补齐花费后直接形成报销。
- 管理员个人报销：我的报销 -> 记一笔，或进入报销整理工作台匹配花费和发票。
- 管理员工作区切换：同一账号内从“个人”切到“管理”，不切换员工身份。
- 管理员核账：管理后台 -> 按状态/月份/员工筛选 -> 查看待补材料或已提交记录。
- 管理员导出：导出 -> 预览已提交汇总 -> 看到待补材料提醒 -> 导出 Excel 或完整明细包。

## ux

### 设计原则如何回应以上要求

- 普通员工第一屏是“我的报销”，顶部主动作是“新建报销”，下方按状态展示自己的报销记录。
- 本月报销记录使用一张紧凑表格承载待补、待提交和已提交状态；上传佐证与发票均在新建报销工作区内完成。
- 佐证材料支持一次多选上传，发票入口一次上传一张；替票作为报销字段保存并显示为“是/否”。
- “我的报销”主列表只展示已经成形的报销记录，不混入待补材料；待补材料通过顶部提醒和独立页面进入。
- 新建报销保持一页内完成，不做分步骤向导；页面按“填写花费 -> 添加发票 -> 提交”纵向组织，避免重复确认页。
- 宽屏 Web 使用“单笔报销工作台”：左侧是当前报销编辑区，右侧是这笔报销的发票和附件区，底部是高密度的我的报销列表。
- 新建报销在“我的报销”页内展开固定编辑区，不跳转独立页面，也不使用大弹窗；用户提交或保存待补后可以继续录下一条。
- 顶部不做“我的报销 / 新建报销 / 本月概览”三栏入口；顶部只承载页面标题、主动作和必要状态，避免把主路径拆散。
- `随手记一笔` 和 `单独传发票` 收敛到“待补材料”页；它们都是只完成了报销材料的一半，不再作为两个分散入口。
- 待补材料页以报销草稿为主，发票是可归属材料；用户可以把未归属发票归到某条报销草稿，也可以从只有发票的材料补花费生成报销草稿。
- 随手记只记录项目名称、金额、月份和类别，不收备注。
- 发票池作为“添加发票”时的选择来源出现，不直接暴露为普通员工默认工作台；普通员工只传发票的入口放在“待补材料”页。
- 上传发票、OCR 暂存和发票入池是后台支撑动作，普通员工界面用“添加发票”“提交”等任务语言表达。
- 普通员工界面不显示“还差多少”或“金额差额”；发票金额和报销金额不一致时，系统标记为替票，并把该标记带入导出台账。
- 我的报销页和报销整理工作栏都提供交易附件上传入口；这些图片只证明真实付款或订单，不参与发票匹配。
- 发票池条目来自 OCR 识别出的真实发票，不展示已挂到花费项目上的交易记录附件。
- 花费卡片、交易记录附件和发票卡片都提供删除入口，防止误录入卡在待定池里。
- 工作栏支持给同一条花费选择多张发票，不提供单张发票拆分到多条花费的入口。
- 普通用户通过顶部栏进入修改密码，不新增独立设置页。
- 至少关联一张发票后才形成可导出的已提交报销项；发票金额和报销金额不一致时作为替票导出。
- 管理员用侧边栏切换“个人/管理”工作区；个人区保留自己的报销路径，管理区只放台账、员工和导出。
- 导出页默认面向完整台账，同时提示还剩多少记录未补完整。
- 明细包包含多 Sheet Excel 和按月份、公司、员工、报销项归档的附件文件夹。
- Excel 首页先汇总公司主体和人员维度，财务确认主体归属后再进入明细 sheet。
