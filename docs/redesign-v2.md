# JetBao V2 交互重设计方案

## 1. 状态模型

### 当前（V1）

```
draft ──→ submitted
```

`draft` 涵盖"刚创建未匹配"和"部分匹配"，`submitted` 是"已提交待审核"。没有"审核通过"的终态。

### 改为（V2）

```
待匹配 ──(用户提交)──→ 已匹配 ──(管理员审核)──→ 已完成
  ↑                       │                        │
  └─── 打回 ←─────────────┘                        │
  ↑                                                 │
  └─── 撤销审核 ←───────────────────────────────────┘
```

**注意：匹配发票 ≠ 提交。** 匹配只是建立发票和花费的绑定关系，不改变记录状态。用户确认无误后点「提交」才进入 `matched`。

| 状态 | 含义 | 谁可见 | 可执行操作 |
|---|---|---|---|
| `pending`（待匹配） | 花费已创建，可能已部分/完全匹配发票，但未提交 | 自己的当月报销页 | 匹配发票、补充佐证材料、编辑、删除、**提交**（金额够时） |
| `matched`（已提交） | 用户已确认提交，等待管理员审核 | 自己的当月报销页 + 管理员台账 | 撤回、管理员审核通过/打回、继续补佐证材料 |
| `reviewed`（已完成） | 管理员审核通过 | 所有记录页（历史） | 仅查看，管理员撤销审核 |

### 材料的状态归属

| 材料类型 | 待匹配 | 已提交 | 已完成 |
|---|---|---|---|
| 花费记录 | 出现在「待匹配」区域 | 出现在「已提交」表格 | 出现在历史记录 |
| 发票附件 | 出现在「发票池」（待绑定） | 挂在花费记录下，不独立展示 | 挂在花费记录下 |
| 佐证材料（交易附件） | 挂在花费记录下，随时可补 | 挂在花费记录下，随时可补 | 挂在花费记录下，锁定 |

### 关键规则

- **匹配和提交是两个独立动作：** 匹配发票只是建立绑定，用户可以继续调整；点「提交」才是确认锁定
- 发票一旦绑定到花费，就从发票池消失——它有了归属
- 佐证材料在 `pending` 和 `matched` 状态下都可以补充；`reviewed` 后锁定
- 跨月未匹配的发票在池中保留 6 个月，过期自动隐藏（不删除，可在「所有记录」中找回）
- 撤回（`matched → pending`）：发票绑定保留，佐证材料保留，回到待匹配区继续修改
- 打回（管理员 `matched → pending`）：同上，需填写打回原因
- `reviewed` 状态锁定一切，撤销审核需管理员确认并记录日志

## 2. 页面结构

从原来的 5 个页面浓缩为 2 个：

### 2.1 当月报销（默认首页）

**一句话：本月的所有操作都在这里，不用跳转。**

```
├─────────────────────────────────────────────────────────┤

│  │  [+ 上传佐证材料]          [保存花费]              │   │

│                                                         │

│                                                         │

```

**核心交互：**
- **先记账路径：** 填项目名+金额 → 保存 → 花费卡片出现在「待匹配」区 → 上传发票 → 选发票点「匹配」→ 金额够了卡片出现「提交」按钮 → 确认无误点「提交」→ 进入「已提交」
- **一起记路径：** 上传发票 → OCR 预填金额 → 填项目名 → 点「记录并匹配」→ 花费卡片出现在待匹配区（已绑定发票，金额够时显示「提交」）→ 确认后点「提交」
- **匹配和提交分离：** 匹配只是绑定发票，不改变状态；用户确认所有信息无误后手动点「提交」才锁定
- **金额够了但不想提交：** 用户可以继续补佐证材料、调整匹配、甚至删除重新匹配，直到自己确认才提交
- **补佐证材料：** 待匹配卡片和已提交表格都有入口，随时可补

## 4. 两条用户路径详细流程

### 路径一：先记账，发票后补

```
1. 在快速录入区填项目名、金额、类别
2. （可选）上传佐证材料
3. 点击 [保存花费]
4. → 花费卡片出现在「待匹配」区，状态 = pending
5. 后续某天：上传发票（拖拽到 InvoiceDropzone）
6. → 发票 OCR 完成，卡片出现在「发票池」
7. 点击花费卡片选中，点击发票卡片选中（可多张）
8. → MatchBar 浮现，显示差额
9. 点击 [匹配] → 发票绑定到花费，花费卡片更新已匹配金额
10. 金额足够 → 花费卡片出现 [提交] 按钮
11. 确认无误，上传佐证材料，点击 [提交]
12. → 花费从待匹配消失，进入「已提交」表格，状态 = matched
```

### 路径二：发票和账一起记

```
1. 拖拽发票到 InvoiceDropzone
2. → OCR 自动识别，票面信息显示出来
3. 金额预填到金额输入框
4. 填写项目名（可选填类别）
5. （可选）上传佐证材料
6. 点击 [记录并匹配]
7. → 花费创建 + 发票绑定一次完成
8. → 花费卡片出现在「待匹配」区，已绑定发票
9. → 金额够了：卡片显示 [提交]，用户确认后点提交 → matched
10. → 金额不够：卡片显示还差金额，继续上传发票匹配
11. → 金额超出：需要填写替票说明 → 金额标记为"替票" → 可提交
```

### 佐证材料补充

```
- 在「待匹配」区：点击花费卡片上的 [+ 材料] 上传
- 在「已匹配」表格：每行有 [补材料] 按钮，随时可传
- 在「所有记录」管理员审核前：员工侧 [补材料] 仍可用
- 一旦管理员审核通过（reviewed），材料不可再改
```

## 5. API 变更

### 新增/修改

| 端点 | 变更 | 说明 |
|---|---|---|
| `POST /api/expenses` | 改名（原 `/api/expenses/drafts`） | 创建花费（pending） |
| `POST /api/expenses/with-invoice` | **新增** | 路径二：一次性创建花费 + 绑定发票，返回 pending |
| `POST /api/expenses/{id}/submit` | **新增** | 用户确认提交 pending → matched |
| `POST /api/expense-allocations/batch` | 保留，行为调整 | 仅匹配发票，不自动提交 |
| `POST /api/expenses/{id}/withdraw` | 保留，行为调整 | 撤回 matched → pending，保留发票绑定和佐证材料 |
| `POST /api/expenses/{id}/attachments` | 保留 | 补充佐证材料（pending + matched 均可） |
| `POST /api/admin/expenses/{id}/approve` | **新增** | 审核通过 matched → reviewed |
| `POST /api/admin/expenses/{id}/reject` | 保留，行为调整 | 打回 matched → pending，保留发票绑定，需填写原因 |
| `POST /api/admin/expenses/{id}/unreview` | **新增** | 撤销审核 reviewed → matched |
| `GET /api/expenses?month=&status=` | 保留，加筛选参数 | 当月报销页用 |
| `GET /api/admin/ledger` | 保留 | 所有记录页用 |
| `GET /api/invoice-pool` | 保留，加 6 个月过滤 | 发票池，超过 6 个月的自动隐藏 |

### 状态枚举变更

```python
# V1
EXPENSE_STATUS = ("draft", "submitted")

# V2
EXPENSE_STATUS = ("pending", "matched", "reviewed")
```

### 数据迁移

```sql
-- draft → pending（语义相同）
UPDATE expenses SET status = 'pending' WHERE status = 'draft';
-- submitted → matched（语义相同）
UPDATE expenses SET status = 'matched' WHERE status = 'submitted';
```

## 6. 和 V1 的差异总结

| V1 | V2 | 变化 |
|---|---|---|
| 5 个页面 | 2 个页面（当月报销 / 所有记录） | 浓缩 |
| 记一笔弹窗 → 表格 → 补材料 → 跳工作台 | 记一笔直接出现在待匹配区，不跳转 | 不跳转 |
| 发票上传后手动「加入发票池」 | 上传即入池 | 减少一步 |
| draft / submitted 两态 | pending / matched / reviewed 三态 | 增加终态 |
| 匹配发票 = 自动提交 | **匹配和提交分离**，用户手动确认 | 更有控制感 |
| 提交后不能补材料 | matched 状态可补材料，reviewed 不可 | 更灵活 |
| 撤回 = 发票绑定解除 | 撤回/打回保留发票绑定和佐证材料 | 不丢数据 |
| 管理员只有「打回」 | 增加「审核通过」和「撤销审核」 | 完整审核闭环 |
| 各页面附件展示不一致 | 统一 AttachmentThumb 组件 | 一致 |
| 发票池无时间限制 | 超过 6 个月自动隐藏 | 不堆积 |
| 工作台布局复杂 | 当月报销一屏内 | 视觉流更顺 |

## 7. 已确认

1. **reviewed 状态支持撤销审核：** 管理员操作，需确认弹窗 + 记录日志。✅
2. **佐证材料 matched 状态可补，不通知管理员。** 管理员审核时自然会看到。✅
3. **跨月未匹配发票保留 6 个月。** 超过 6 个月的自动隐藏，数据不删除。✅
4. **OCR 失败可手动填写。** 金额和抬头允许用户手动输入，标记为"手动录入"。✅
5. **匹配和提交分离。** 匹配仅建立绑定，用户确认后手动「提交」才锁定为 matched。✅
6. **撤回/打回保留发票绑定。** 不再删除 `expense_invoice_allocations`，状态回 pending 后用户可调整后重新提交。✅
